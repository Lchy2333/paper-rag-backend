# Paper-RAG 黄金测试集评测报告（最终基线）

> 数据集版本：2026-10-25（93 题）｜ 结果文件：`results/eval_93q_judged.json`（含答案正确性判定）｜ 配置：混合检索 + rerank（线上口径）
> 本报告是黄金测试集的阶段性总结。**当前定位：评测体系完整交付，RAG 侧逻辑冻结不再迭代**，本报告即为该版本的存档基线。

---

## 1. 摘要

在 12 篇真实论文/规范语料（约 1300 chunk）上，构建了 **93 道题**的黄金测试集（83 道计分题 + 10 道拒答负样本），实现可用证据原子 **100% 覆盖**（91/91，排除 1 篇文本层毁坏语料），全部通过 G0 数据门禁。最终基线：

| 指标 | 数值 | 含义 |
|---|---|---|
| page Recall@10 | **0.775** | 检索把证据页捞回 top-10 的比例 |
| page MRR | **0.694** | 证据排到首位的倒数排名均值 |
| chunk Recall@10 | **0.498** | top-10 中含完整证据块的比例（受切分质量拖累） |
| 引用页召回 citeR | **0.715** | /ask 回答引用页覆盖证据页的比例 |
| **答案正确率** | **0.639** | 回答内容对照 keypoints 判 correct 的比例（LLM 裁判） |
| 要点覆盖率 | **0.677** | 回答覆盖的参考要点数 / 总要点数 |
| 拒答准确率 | **1.000（10/10）** | 语料外问题全部正确拒答 |
| 幻觉违例 | **0** | 无一例命中 forbidden_claims 编造主张 |

一句话结论：**单证据检索（R1）已可用（0.86/0.72）；跨文档多证据（R4）与表格级证据完整性（chunkR 0.17）是明确短板；答案正确率 0.639 的缺口 92% 由检索失败传导（13 道 wrong 里 12 道检索背锅），生成侧独立问题仅 1 例；防幻觉能力（拒答 100% + 零违例）达到生产可接受水平。**

## 2. 评测体系设计

### 2.1 三层数据模型

```
docs.json（12 篇语料台账，sha256 校验）
  → facts.json（101 条 verbatim 证据原子，quote 逐字摘自 PDF 文本层）
    → golden_queries.json（93 道题 = 问题 + 证据引用 + 答案 keypoints + 判分规则）
```

quote 铁律：证据必须程序化从 PDF 截取、不得手打，配四步归一化（NFKC → 去空白 → 连字符统一 → 波浪号统一）。这保证了"证据-原文-chunk"三层逐字可校验。

### 2.2 双轴难度分级

- **检索轴 R1-R4**：单证据 → 表格/多值 → 同文档多证据 → 跨文档对比/冲突
- **生成轴 A1-A4**：直接抽取 → 数值/对比 → 公式/计算 → 推理与冲突归因
- 每题打双标签，指标可按难度切片——这是本体系区别于"一个总分"评测的核心价值

### 2.3 两道闸

1. **G0 数据门禁**：页级校验（quote 落在 PDF 原文）+ chunk 级校验（quote 落在入库 chunk，三态 OK/SPLIT/MISSING）。数据不合格禁止进入评测。
2. **评测 runner**：调真实 `/search`（SSE）+ `/ask` 接口，全库检索，输出检索轴与生成轴指标。拒答类题目单独统计，不污染检索指标分母。

### 2.4 数据集构成

| 维度 | 分布 |
|---|---|
| 检索难度 | R1×57（74%）· R2×6（8%）· R3×4（5%）· R4×16（13%） |
| 生成难度 | A1×52（65%）· A2×22（27%）· A3×8（10%）· A4×1（1%） |
| 行为类型 | answer×72 · attribute_conflict×11 · refuse×10 |
| fact 覆盖 | 91/91 = 100%（排除 R07 文本层毁坏语料的 10 条） |

与工业界基准对照（CRAG：Simple+条件类占 43%；MultiHop-RAG：多跳/对比/推理类占 88%）：本数据集简单题占比偏高（74%），这是"每条 fact 各出一题"策略的自然结果——好处是**归因粒度精确到单条证据**，代价是高难度样本偏少（A4 仅 1 题）。R4 档通过 fact 复用已从 4 题扩到 16 题。

## 3. 最终基线结果

### 3.1 总体（83 道计分题）

| 指标 | 数值 |
|---|---|
| page Recall@10 | 0.775 |
| page MRR | 0.694 |
| chunk Recall@10 | 0.498 |
| 引用页召回 | 0.715 |

补充分布：**44/83（53%）的题目达到"证据排第一"的完美命中**；25 题存在不同程度的证据丢失。

### 3.2 按检索难度（R 轴）

| 档 | n | pageR | MRR | chunkR | citeR | 判读 |
|---|---|---|---|---|---|---|
| R1 单证据 | 57 | 0.860 | 0.721 | 0.632 | 0.807 | 主体能力可用 |
| R2 表格取数 | 6 | **1.000** | 0.792 | **0.167** | 1.000 | 页全中、块全碎 |
| R3 同文档多证据 | 4 | 0.500 | 0.550 | 0.375 | 0.500 | 多证据召回掉半 |
| R4 跨文档 | 16 | **0.458** | 0.594 | 0.177 | **0.333** | 最大短板 |

### 3.3 按生成难度（A 轴）

| 档 | n | pageR | MRR | chunkR | citeR | 判读 |
|---|---|---|---|---|---|---|
| A1 抽取 | 52 | 0.817 | 0.674 | 0.577 | 0.740 | 最稳 |
| A2 数值 | 22 | 0.727 | 0.705 | 0.341 | 0.682 | 表格数值切分受损 |
| A3 公式 | 8 | 0.688 | 0.750 | 0.438 | 0.688 | 引导句锚定有效 |
| A4 冲突推理 | 1 | 0.333 | 1.000 | 0.333 | 0.333 | 样本不足不下结论 |

**规律**：pageR 与 citeR 高度同步（0.775 vs 0.715），说明生成侧引用忠实跟随检索结果，**没有出现"检索到了却引用错"的独立生成问题**——短板全部在检索侧。

### 3.4 消融对比（93 题四档全量，`eval_93q_A/B/C/D_*.json`）

| 配置 | pageR@10 | MRR | chunkR@10 |
|---|---|---|---|
| A 纯向量（无 rerank） | 0.661 | 0.526 | 0.420 |
| B 混合（无 rerank） | 0.685 | 0.527 | 0.456 |
| **C 混合 + rerank（线上）** | **0.775** | **0.694** | **0.498** |
| D 纯向量 + rerank | 0.775 | 0.686 | 0.498 |

**贡献拆解**：

- **rerank 是主要贡献者**（C−B）：pageR +9.0pt、MRR +16.7pt。C vs B 的 MRR 提升 0.167，远超预设的 go/no-go 门槛（≥0.05），**rerank 生产开启获得数据背书**
- **hybrid 独立贡献正但小**（B−A）：pageR +2.4pt、chunkR +3.6pt——作用是字面路兜底（公式/编号/专名精确匹配）
- **C vs D**：pageR 持平、MRR 略胜（+0.8pt）——当前线上配置（混合+rerank）为四档最优，生产选择得到验证
- **rerank 意外收益**：扩池（30 候选精排）把含证据的 chunk 排进 top-10，chunkR 从 0.420（A）抬到 0.498（C/D）——rerank 不只治"排序病"，对粗排漏排的证据块也有召回补救
- 已知风险：rerank（cross-encoder）偏好"正文条款"、轻视"脚注/注释类证据"（GB 规范注释题被压后一位）

### 3.5 拒答轴与答案正确率轴（LLM 裁判，`eval_93q_judged.json`）

**裁判机制**：判定分三通道——数值题程序判（正则抽取 + tolerance 比对 + 键值邻近匹配防互换，零成本全客观）；语义题与拒答题由**异源 LLM 裁判**（SiliconFlow Qwen2.5-72B-Instruct，与被测方舟 deepseek-v4-flash 异源异构，规避自我偏好）对照 keypoints / forbidden_claims / judge_rubric 打分。裁判上岗前过 8 用例标定集（已知对/错样本 8/8 通过；标定第一轮曾抓出数值互换误判 bug 并修复）。本轮 93 题判定 0 失败。

**答案正确率结果（83 道计分题）**：

| 指标 | 数值 | 说明 |
|---|---|---|
| answer_accuracy（correct） | **0.639**（53 题） | 回答完整覆盖全部要点 |
| answer_partial_rate | 0.205（17 题） | 要点部分缺失（多为漏 1 条要点） |
| answer_wrong_rate | 0.157（13 题） | 答错/未答 |
| keypoint_coverage | 0.677 | 要点级覆盖率 |
| 幻觉违例 | **0** | 无一回答命中 forbidden_claims |

**按检索难度切片**：

| 档 | 正确率 | 对照 pageR |
|---|---|---|
| R1 单证据 | 0.754 | 0.860 |
| R2 表格 | 0.833 | 1.000 |
| R3 多证据 | 0.250 | 0.500 |
| R4 跨文档 | 0.250 | 0.458 |

**关键归因——正确率缺口是谁的锅**：13 道 wrong 中 **12 道检索背锅**（9 道检索全失败 + 3 道部分失败，模型没拿到证据自然答不出）；**生成侧独立问题仅 1 例**（Q-R1-A3-03：证据命中但公式结构还原错误）。另有 7 道"检索满分但答不全"的 partial（漏要点型：如漏"涂底涂"、漏"0.9 倍上限"）。**结论：0.639 与 0.775 的差距几乎全部由检索失败传导，生成侧（deepseek-v4-flash + 引用机制）本身相当可靠——这直接指明了"修检索优先于修生成"的资源投向。**

**拒答轴（LLM 裁判口径）**：10/10 判 refused，幻觉编造 0 例。

## 4. 失败模式归因（25 道非满分题）

**① 跨文档深层证据召回失败（13 题，全部 R4）** — 最大失败源
top-10 被相关文档的摘要页/高频页霸占，证据所在的正文中后段页被挤出。典型：Q-R4-A1-01/02 的证据在 p2/p9，top-10 全是 p1 摘要。**这是 embedding 对"文档相关"与"证据位置"区分不足的结构性问题。**

**② 同主题文档互相挤占（8 题，R1 零召回）**
语料中有多篇主题高度相似的论文（R03/R08/R12 同为约束混凝土、R10/R11 同为钢管约束）。提问指向其中一篇时，另一篇的相关页占满 top-10。典型：Q-R1-A1-03（问 R08 剪切角，R12 霸榜）。

**③ 表格证据块切碎（chunkR 0.167，R2 档全部）**
页级 100% 命中但 chunk 级几乎全灭——表格在解析/分块阶段被粘连或断行，完整 quote 不存在于任何单个 chunk。检索再强也无解，属解析器范畴。

**④ 多证据部分召回（R3 档）**
同文档两处证据只捞到一处（pageR=0.50），第二处深层页未进 top-10。

**⑤ 排序精度不足**
部分题证据进了 top-10 但排位靠后（MRR<0.5），实际有效可用位置只有前 3-5。

## 5. 样本量演化：评测集构成决定结论

| 阶段 | 题数 | pageR@10 | MRR | 说明 |
|---|---|---|---|---|
| v1 | 5 | 0.867 | 0.767 | 手工精选，全部简单题，**指标虚高** |
| v2 | 20 | 0.692 | 0.571 | 刻意补难题，**指标骤降** |
| v3 | 77 | 0.803 | 0.710 | fact 全覆盖，R1 占 74% 拉回均值 |
| **v4（最终）** | **93** | **0.775** | **0.694** | +R4 复用 +拒答轴，稳定收敛 |

教训：**5 题样本时"四档消融无差异"的结论是错的**——不是没有差异，是粒度和样本量都测不出来。评测结论的可信度与数据集构成直接绑定，报告指标时必须同时报告分布。

## 6. 标注事故案例：负样本必须验证"确实不在语料"

首版拒答题 Q-R1-A1-49 问"Muttoni 教授任职于哪所大学"，设计假设是该信息不在语料。实测模型回答"洛桑联邦理工学院"并给出引用——**复核发现 R06 论文第 1 页作者栏明确写着 EPFL**。模型是对的，题是错的。

修正：换成"Muttoni 的博士导师是谁"（确认两篇论文均无此信息），重跑后拒答 10/10。

方法论沉淀：**拒答负样本出题前，必须对全部语料做关键词反查验证**；评测体系的价值不仅在度量系统，也在系统性揪出标注错误。

## 7. 结论与边界

**已达成的**：
- 真实语料 + 逐字可校验证据 + 双轴分级的完整评测体系（对标 RAGAS 的检索/生成分轴思路，粒度更细）
- G0 数据门禁（页级 + chunk 级三态）保证"数据不合格不出现在评测里"
- 消融开关（hybrid/rerank 请求级三态）+ 拒答轴（对标 CRAG 的 Null 类目）
- **答案正确性判定**：数值程序判 + 异源 LLM 裁判（先标定后上岗），把评测口径从"检索质量"补齐到"回答内容质量"
- 可复现基线：数据集版本、结果文件、报告三者严格配套

**明确边界（RAG 侧冻结，不再迭代）**：
- 跨文档召回（R4=0.458）——改进方向是检索侧（page 级去重/MMR/更大的候选池），工程收益递减
- 表格证据完整性（chunkR=0.167）——瓶颈在解析器表格识别，不在检索
- A4 样本仅 1 题——冲突推理能力未充分标定
- **裁判侧**：单裁判（无多裁判交叉验证），判分质量受 keypoints 标注质量约束；数值互换场景程序判只能保守降级 partial；裁判为 LLM，存在低概率误判（已用标定集 + reason 留痕缓解，可人工抽查）

**如果未来重启优化的优先级**（按投入产出比）：
1. 同主题文档去重/MMR（解失败模式①②，预计 pageR +5~8pt；13 道 wrong 里 12 道是检索传导，检索侧修复对正确率的杠杆最大）
2. 表格分块保完整（解失败模式③，chunkR 弹性最大）
3. R4 扩题至 30+ 并补 A4（提升跨文档结论置信度）
4. 生成侧仅 1 例独立问题（公式还原），排最后
